Spec convention: every version link is a compare-to-previous-version link,
EXCEPT the very first/oldest released version, which uses /releases/tag/.

This repo:
$ git tag -l | wc -l
0

No tags exist yet, so the very next version cut by /solodev:ship IS this
repo's first-ever tagged release. For THIS run, /releases/tag/ happens to be
correct per the spec's own oldest-version convention.

Defect: the skill hardcodes /releases/tag/ for every future release, with no
branch for "is there a prior tag." Starting with the SECOND time /solodev:ship
runs (run #5's release or later), the correct format per Keep a Changelog
becomes /compare/v<previous>...v<version>, and the skill will keep emitting
/releases/tag/v<version> instead — a spec-incorrect link that this run's
execution cannot surface, because there is no previous tag yet to expose the
missing branch.

Severity: S3. Cosmetic — a wrong hyperlink target in a changelog, not a lost
changelog entry or a wrong version number. Does not block or corrupt this
run's release.
