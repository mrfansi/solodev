Half of this ("scored normally", "subject to the audit cadence") is duplicated in
§10's backlog table. The other half — that a feature deferred BY THE CADENCE
specifically and automatically becomes the next run's first candidate, and that the
report must say so — appears nowhere in specs/LOOP.md. §8's "this plan binds the
next run's Phase 1 as its default candidate" is a different, weaker guarantee: it
describes whatever plan the CURRENT run chooses to write, not an automatic promise
that a cadence-deferred feature specifically gets first refusal next run. A run
could write any plan it likes for run N+1 without violating anything currently in
specs/LOOP.md, whereas the deleted skill text made that non-optional.

The run's own duplication-audit (01-duplication-audit.txt) collapsed this whole row
to the one-liner "feature deferred by the audit cadence DUP -> §3 Phase 1" and
marked it duplicate. That is a false positive: the script (and the manual
correction pass that followed it) matched the general "deferred by cadence"
concept but never checked the specific consequence clause standing behind it. The
audit's manual correction pass only re-checked items the script had flagged
"NOT IN PROTOCOL — keep" (to see if they should flip to DUP); nothing re-checked
items already flagged DUP for a possible flip the other way. That blind spot is
exactly the one this clause fell into.
